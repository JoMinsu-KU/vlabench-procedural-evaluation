## Contents

- `model_outputs/<model>/experiment_a/`: raw symbolic responses and scores
- `model_outputs/<model>/experiment_b/`: raw procedural responses, validation outcomes, and execution results
- `model_level_statistics/`: aggregate three-model statistics from the released runs
- `outcome_audits/`: paired-outcome and procedural-complexity audits
- `positive_control/`: canonical reference-procedure viability evidence
- `reported_statistics/`: tables regenerated by the analysis script
- `validation_evidence/`: recovered Oracle contract, native-path, and live-parser validation evidence

The positive control is not a model result. It establishes that canonical procedures can pass the packaged validation and native execution path under the stated retry policy.

## Oracle diagnostic controls

| Model | Full procedural | Phase-oracle | Target-oracle |
|---|---:|---:|---:|
| Qwen3-VL-8B | 80/2,133 (3.75%) | 427/2,133 (20.02%) | 488/2,133 (22.88%) |
| Gemma-3-12B-it | 57/2,133 (2.67%) | 344/2,133 (16.13%) | 585/2,133 (27.43%) |
| InternVL3-8B | 40/2,133 (1.88%) | 314/2,133 (14.72%) | 191/2,133 (8.95%) |

The Phase-oracle fixes reference phase/order and evaluates model-selected targets. The Target-oracle evaluates model-generated phase/order and reads reference targets only after a valid sequence. Both controls improve over full procedural generation for every model under task-clustered bootstrap intervals. The two oracle conditions must not be ranked inferentially because all Target-minus-Phase intervals include zero.
